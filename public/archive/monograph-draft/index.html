Offline transcription

FoziScribe

An offline transcription app for audio and video files. It runs faster-whisper locally inside a Gradio interface, with a fast and an accurate model mode, segment and optional word-level timestamps, .txt and .srt exports, session history, and an automatic CUDA-to-CPU fallback so it keeps working without a GPU.

  • Python
  • faster-whisper
  • Gradio
  • CUDA

Local text-to-speech

Text-to-Audio Studio

A local narration studio: pick a voice and a preset, adjust the speed, and synthesise WAV audio on your own GPU. Long scripts up to 200,000 characters are split at paragraph, sentence and clause boundaries, then stitched back into a single file — served by FastAPI with a plain HTML, CSS and JavaScript frontend.

  • Python
  • FastAPI
  • Kokoro
  • JavaScript

Voice assistant for Linux

Mustaqeem

A terminal voice assistant for Arch Linux. The wake word, speech-to-text and spoken replies all run locally; only the reasoning step uses a configured OpenAI-compatible provider, with an offline rule-based fallback. Actions go through a fixed set of structured tools — no raw shell access — and destructive commands confirm before running.

  • Python
  • openWakeWord
  • piper-tts
  • Arch Linux

A study-resource portal for colleges: browse by college, branch, year, subject and chapter, with separate role-based flows for students and administration. Built with Express and SQLite, and documented in a repository that is not public.

AI image editing

LocalMind

An image editor that can work offline or online. Offline mode talks to a local Stable Diffusion instance — no accounts, no requests beyond localhost; online mode sends the same workflow to cloud providers through an API key you store in the browser. React and Vite on the front, FastAPI behind it.

  • Vite

Background

Where I am, how I work, and what I’m building toward.

I’m a second-year B.Tech student in computer science, specialising in cyber security — and I learn by building things that work.

Most of what I build keeps data on the machine it started on: transcribing audio, synthesising narration, listening for a wake word. Local-first is a practical choice first and a security habit second — it simply means fewer places for anything sensitive to end up.

That habit shows up in the details. Destructive commands ask before they run, file access is confined to the home directory, and no action ever gets a raw shell. Security is my specialisation, and I treat it as a design constraint rather than something bolted on at the end.

Alongside my studies I take on freelance work and keep learning through independent projects. I care about thoughtful engineering, clear interfaces, and software that respects the people using it.
